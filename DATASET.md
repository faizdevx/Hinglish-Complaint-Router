# DATASET.md

All data comes from one Hugging Face dataset repository, **`cmul8-hf/IndicJevBench`** (publisher: cmul8; `https://huggingface.co/datasets/cmul8-hf/IndicJevBench`; dataset card licence **CC BY 4.0**; card last modified 2026-09-24 per the Hub API). Files were retrieved on **2026-10-07** by `scripts/download_data.py`; SHA-256 and byte sizes are in `data/raw/download_info.json`. Every raw record carries a `provenance` field, which this document reproduces. Statements below marked *(unverified)* are things the dataset card does not document and I did not independently check.

Each IndicJevBench record is one *question about a message* (`state` = the message, `question.options` = answer choices, `expected` = gold index). All four subsets are tagged `split: "v1"`, so **no official train/val/test split exists**; splits used here are my own (see below).

## Category legend

| Category | Meaning |
|---|---|
| **public benchmark source** | text originates from a published benchmark dataset |
| **machine-translated** | benchmark text auto-translated by an MT system (quality *(unverified)*) |
| **synthetic / constructed** | text generated by an LLM for this benchmark; **not naturally occurring** |

## Subsets used for training / evaluation

### 1. `fintech_banking77`: intent labels (77 classes)

| Field | Value |
|---|---|
| Original source | Banking77 (PolyAI), as redistributed in IndicJevBench |
| File / licence | `v1/fintech_banking77.jsonl` · CC BY 4.0 (record `license` field) |
| Examples | 7,816 raw → 7,816 unique (lang, text) after normalisation; 0 malformed, 0 label conflicts |
| Languages (rows) | en-Latn 1,318 · hi-Deva 1,090 · te-Telu 1,096 · kn-Knda 1,094 · ml-Mlym 1,079 · bn-Beng 1,075 · ta-Taml 1,064 |
| Labels | 77 banking-support intents (`question.options[expected]`), e.g. `card_arrival`, `compromised_card`. Each record shows only a subset of the 77 options; the gold string is resolved from `options[expected]`. |
| Provenance | **English (1,318 rows): public benchmark source** (`origin: banking77`). **Other six languages (6,498 rows): machine-translated** (`origin: banking77+mt`, note: "Banking77 translated to Indic via NLLB-200"). How the original English queries were collected is not stated in the IndicJevBench card *(unverified)*. Translation quality has not been human-checked *(unverified)*. |
| Not present | **Romanised Hindi / Hinglish: none.** No code-mixed intent examples. |
| Processed split | 70/15/15 by unique (lang, text), stratified by intent, seed 42 → train 5,471 · val 1,172 · test 1,173 |

Each item occurs in exactly one language (no id is shared across languages), so translated twins of one source query cannot be linked from the data and could in principle fall into different splits *(documented limitation)*.

### 2. `synthetic_enterprise`: urgency, escalation (and routing, not trained)

| Field | Value |
|---|---|
| Original source | Generated by cmul8 ("qwen3-235b + deepseek checker", per record `provenance.notes`) |
| File / licence | `v1/synthetic_enterprise.jsonl` · CC BY 4.0 |
| Examples | 444 question-rows over **222 unique texts**: urgency 175, escalation 177, routing 92 |
| Languages (rows) | hi-Deva 174 · hi-Latn (Romanised Hindi / Hinglish) 270. **Hindi-only** |
| Labels | urgency 1–5 (stored index 0–4 → very_low/low/medium/high/critical; counts over the 175 labelled texts: very_low 1, low 12, medium 37, high 57, critical 68), escalation yes/no ("is human intervention required?", 67% yes), routing (two different department option sets: banking-style and e-commerce-style) |
| Provenance | **synthetic / constructed**: `origin: synthetic`. These are LLM-written messages and LLM-assigned labels. They are **not** real customer messages and the labels are **not** human annotations *(unverified whether any human review occurred)*. |
| Processed split | one row per unique text (labels merged), 70/15/15 by text, stratified by language, seed 42 → train 124 urgency / 123 escalation · val 24 / 28 · test **27 / 26** labelled texts |
| Use here | urgency head, escalation head. **Routing labels (92 rows, hi-Latn only, two taxonomies) are kept in `route_gold` but not trained on or evaluated**: too few, and they carry no intent labels to validate the intent→route mapping. |

## Subsets inspected but NOT used for training

| Subset | Items | Why not used |
|---|---:|---|
| `intent_massive`: MASSIVE (Amazon), 60 voice-assistant intents ("set an alarm", "play music") in 7 languages (`origin: massive`, note "MASSIVE official test split"; CC BY 4.0) | 57,922 | Voice-assistant commands, not support messages or complaints; 20 options per item; no Hinglish. Would add 58k rows of an unrelated domain and dominate CPU training time. |
| `hinglish_lid`: COMI-LINGUA (IIT Gandhinagar) text with a script-detection question (`origin: comilingua`; CC BY 4.0) | 3,220 | Only labels are Devanagari-only (275) / Latin-only (899) / both (2,046), derived by the dataset authors from Unicode script presence. Used **only** to sanity-check `src/preprocessing.detect_script` (3,219/3,220 agree; the one miss is a stray `Ó` the upstream rule evidently ignores). **Data-quality note:** every record is tagged `lang: hi-Latn`, but 2,321 of them contain Devanagari. The language tag in this subset is not reliable. |

## Consequences that shape the project (read before interpreting any number)

1. **No dataset contains real customer complaints with urgency/escalation labels.** The project is a *multilingual message-intent routing* study with banking intents, plus a small synthetic urgency/escalation component. It must not be described as trained on real customer complaints.
2. **No labelled Hinglish intent data.** Intent accuracy on Romanised Hindi is *not measured*. (hi-Latn rows exist only in the synthetic set, without intent labels.)
3. **No text carries all three labels.** Multi-task training uses masked losses: each row contributes only the loss terms for labels it has.
4. Because of (3) the urgency/escalation heads are trained on ~120 texts, all Hindi; their behaviour on the six other languages is zero-shot transfer from the shared encoder and is unmeasured.
